# بيتنا POS

توثيق هيكل المشروع وقواعد إضافة المكونات موجود في [ARCHITECTURE.md](./ARCHITECTURE.md).

نسخة أولى لنظام سطح مكتب لمطعم أكل بيتي يعمل بالدليفري. الواجهة عربية بالكامل وتدعم:

- نقطة بيع منفصلة للأكل المطبوخ والأكل الطازة.
- سجل للعملاء وعناوين التوصيل.
- إضافة العميل مباشرة من نقطة البيع وفتح ملفه وسجل طلباته.
- إضافة وتعديل الأصناف والتصنيفات مع السعر والتكلفة والتوفر.
- الدفع نقدي أو إنستاباي أو فودافون كاش.
- فصل حالة الطلب عن حالة التحصيل.
- فواتير معلقة مع الدليفري وتسويتها لاحقًا.
- شاشة تجميع أصناف للمطبخ.
- متابعة بدء التحضير وتجهيز الطلب.
- تايمر حي لكل طلب مع تنبيه التأخير وفصل مطبخ المطبوخ عن تجهيز الطازة.
- مرحلة مستقلة للتغليف والتجميع قبل جاهزية الطلب.
- طلبات مجدولة حسب موعد التوصيل.
- إدارة المندوبين وإسناد الطلبات الجاهزة.
- اختيار مندوب المطعم أو شركة توصيل مباشرة من نقطة البيع.
- تعديل الطلبات وتسوية فرق المخزون والحسابات تلقائيًا.
- خروج وتسليم الطلب وتتبع العهدة.
- تسوية عهدة المندوب مع المصروف والفرق.
- خزنة ومصروفات وحركات وردية.
- تقرير يومي ومبيعات حسب طريقة الدفع.
- تقرير أداء التوصيل والتسويات.
- طباعة فاتورة حرارية 80mm وتجميع المطبخ.
- إدارة المكونات وأرصدة وحدود إعادة الطلب.
- وصفات الأصناف وحساب التكلفة وهامش الربح.
- خصم مكونات الوصفة تلقائيًا عند تأكيد الطلب.
- سجل مشتريات واستهلاك المخزون.
- رسالة تأكيد طلب جاهزة لواتساب.
- نسخ احتياطي واسترجاع كامل للبيانات.
- حفظ محلي في SQLite عند تشغيل تطبيق Tauri.
- صفحة إعدادات للوجو واسم المطعم وبيانات الفاتورة ورسوم التوصيل وتنبيهات المطبخ والنسخ الاحتياطي.

## تشغيل الواجهة أثناء التطوير

```powershell
npm install
npm run dev
```

ثم افتح `http://localhost:1420`.

عند التشغيل في المتصفح تُحفظ بيانات التطوير في Local Storage. عند تشغيل نسخة سطح المكتب يستخدم التطبيق قاعدة SQLite باسم `beitna.db`.

## تشغيل نسخة سطح المكتب

يتطلب تثبيت Rust وMicrosoft C++ Build Tools وWebView2:

```powershell
npm run desktop:dev
```

## إنشاء ملف تثبيت Windows

```powershell
npm run desktop:build
```

ملف التثبيت الناتج يظهر داخل:

`src-tauri/target/release/bundle/nsis`
